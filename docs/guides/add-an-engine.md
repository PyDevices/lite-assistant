# Add an engine

Add a module to `src/lite_assistant/engines/` whose name ends in `_engine.py`, e.g. `coqui_engine.py`. In it, define a class that inherits from `TTSEngine` (speech), `STTEngine` (transcription), `LLMEngine` (chat), `EmbeddingEngine` (embeddings), `DepthEngine` (depth), `DetectionEngine` (objects), `SoundEngine` (sounds), `ClassifierEngine` (text classification), `ImageEditEngine` (image editing), `QualityEngine` (image quality), `OCREngine` (reading text), `SegmentEngine` (finding things by name), `FaceEngine` (what a detected face shows) `PoseEngine` (a detected person's or hand's joints) or `ImageClassifierEngine` (naming what a photo shows, such as a plant), `DenoiseEngine` (noise removal), `SpeakerEngine` (telling voices apart), `LineEngine` (lines to follow), `ActionEngine` (actions across video frames), `PitchEngine` (the note heard) or `RerankEngine` (putting documents in order). The server discovers it at startup, and unless it's one of the kinds loaded at startup (`EAGER` in `engines/__init__.py`), creates it on first use; a `MODEL_ID` class attribute lets `/v1/models` name its model without loading it. [`engines/tflite.py`](../../src/lite_assistant/engines/tflite.py) has what an engine on `.tflite` graphs from the Hub needs: finding and downloading its files, loading a graph and running it, and decoding a photo; `nima_engine.py` is a short example. `lite-assistant setup` calls its `setup()` class method to download what it needs.

[Find LiteRT models](find-litert-models.md) explains finding LiteRT models on Hugging Face, checking one before writing code, and adding it as an engine, with MoGe-2 as the example.
