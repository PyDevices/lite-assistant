# Use the chat page

Open `http://localhost:5000/` for a chat with the LLM in the browser. It needs no internet, and uses only the server's own APIs:

- **Chat** goes through `/v1/responses` in a stored [conversation](../reference/endpoints.md), so a reload shows it again, even after the server restarts. **New chat** (+) starts another.
- **Chats** (☰, top left) pops out the list of your chats from the left edge: pinned ones first, then by when they last changed, under Today, Yesterday and Earlier. Clicking one loads it. Each is named after its first message. Hovering one shows its **pin**, **rename** and **delete** buttons; on a touch screen, its **⋯** button does. Delete takes it off the list with an **Undo** for a few seconds, and closing the list makes it final. The list comes from `GET /v1/conversations`, which OpenAI's API doesn't have: a user's conversations, the last changed first, each with its `updated_at`; names and pins are the conversation's `title` and `pinned` metadata.
- **The message box** holds what you'll send, with a row of controls under the text: **+** to attach files, the model, the context arc, record, live and send.
- **The model** (the pill by the send button, such as "Gemma 4 E2B Medium") opens a menu that picks the model for each reply, and for live mode, and how long it [thinks](let-the-model-think.md): **Off**, **Low** (up to 512 tokens), **Medium** (2048) or **High** (no limit). The thoughts show as they come, then fold away under the reply. The first reply after a switch shows "Loading…" while the server [swaps models](switch-models.md). The menu's last item, **Add or remove models…**, searches Hugging Face for LiteRT-LM chat models, downloads one with a progress bar, and deletes those not in use.
- **Stats** under each reply: the time to its first token, tokens a second (left out when the reply ran a tool, which spends tokens before any show), and how many tokens. The arc by the model shows how much of the model's context the chat fills, with the percentage; it turns amber at 75% and red at 90%. Hover it for the counts.
- **Attaching** (+, paste or drop): images, shrunk to 1024 px, for a model that can see; audio files (MP3, M4A, WAV, Ogg, FLAC and others the browser plays), as voice clips of up to 2 minutes; and documents, PDFs, Word files and text files, up to 20 MB, which the server reads into text. Photos the model edits for you show in its reply, on a checkerboard where they're transparent.
- **Voice clips:** the mic button records one, which the model hears when it's sent. Its **Dictate** button writes what it says into the message instead, with Moonshine, and **Translate** puts it into English.
- **Suggestions** (in settings, off at first) asks the model to end each reply with three follow-up questions. The first one that's the user's own question, not one asking the user something, becomes the message box's hint, and **Tab** writes it in to edit or send. The suggestions are never shown or spoken as part of the reply. The model writes them in the same reply, about 30 more tokens, so they cost about a second. Asked for just one, Gemma 4 E2B often asked the user something instead. Picking the best of three with the reranker took 2 to 4 s and 1 GB more memory and chose no better, so it isn't used. Qwen3-0.6B garbled them, so models under 2B, by the size in their name, aren't asked.
- **Speak replies** (the speaker button) reads each reply aloud as it's written, in the voice chosen in settings.
- **Live** (the waveform button) is a spoken conversation over `/v1/realtime`, interrupted by speaking over it. Its turns are added to the chat when it ends.
- **Search** ranks the chat's messages, images and clips by meaning, with `/v1/embeddings`.
- **Settings** (the gear): voice, enrolled voices (record 8 s of someone talking to add theirs), instructions, max output tokens, temperature, and whether the model may use the [built-in tools](../reference/built-in-tools.md). Settings also names the LLM answering, and live mode shows it too. Built-in tool calls show under the reply.
- **Instructions** start out asking for replies that read aloud well: plain sentences without markdown, lists or emoji, symbols written out as they're spoken, short unless asked for more, in the user's language, and saying so rather than guessing about what the model can't know. Edit them however you like; Restore default puts them back, and clearing them sends none.

Browsers allow the microphone only in a secure context: at `localhost`, or over https. From another machine, [serve it over https](serve-over-https.md), or in Chrome add its address to `chrome://flags/#unsafely-treat-insecure-origin-as-secure`.
