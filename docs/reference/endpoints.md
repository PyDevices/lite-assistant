# Endpoints

- **`/v1/chat/completions`:** chat with the LLM, streamed or not. Messages may carry OpenAI `input_audio` parts (base64 WAV), which the model hears directly, `image_url` parts, which it sees: a `data:` URL, or an http(s) URL the server fetches (up to 20 MB), and `file` parts with `file_data`: a PDF, Word file, photo of a page or any text file, which the server reads into text for the model, as `search_notes` reads [documents](../guides/search-your-documents.md), up to 60,000 characters. Function `tools` work too; see [Function tools](../guides/call-your-functions.md). The model can also use the server's own [built-in tools](built-in-tools.md), such as the clock. `reasoning_effort` turns [thinking](../guides/let-the-model-think.md) on or off, and the thoughts come back as `reasoning_content`. `response_format` asks for [JSON](../guides/get-json-replies.md). Beyond OpenAI's fields, `usage` has `context_tokens`: how much of the model's context the reply filled, which tells a client when to start over.
- **`/v1/responses`:** OpenAI's newer chat API, on the same model, streamed or not. Input messages may carry `input_text`, `input_image`, `input_audio` and `input_file` parts, an `input_file` read into text as a chat `file` part is. Function `tools` give `function_call` output items, answered with `function_call_output` input items. Built-in tool calls show as `mcp_call` items. `reasoning.effort` turns [thinking](../guides/let-the-model-think.md) on or off, and the thoughts come back as `reasoning` items. Responses are stored unless `store` is false, so `previous_response_id` can chain onto one, and `GET`/`DELETE /v1/responses/{id}` and `/v1/responses/{id}/input_items` work; `background` responses generate on their own and can be cancelled with `/v1/responses/{id}/cancel`. The store is in memory: a restart forgets it, and past 1000 responses the oldest go.
- **`/v1/conversations`:** server-held conversations: create, retrieve, update, delete, and list, add, get and delete their items; and, beyond OpenAI's API, list a user's conversations, the last changed first. A response made with `conversation` set continues it, and adds its input and reply to it. Each user's are their own, kept in a SQLite database in the data directory, `conversations.db`, so they outlast a restart. They're kept until deleted, unless `serve --forget-chats-after DAYS` forgets those unchanged that long; one whose metadata has `"pinned": "true"` is kept anyway.
- **`/v1/files`:** each user's files: upload, list, retrieve, get the content of, and delete. An upload of any purpose but `vision` goes in the user's notes folder, which [`search_notes`](built-in-tools.md) searches, so it's how to add a document to their notes; notes put in the folder directly are listed too. Files of purpose `vision` go in their media folder, `users/<name>/media` in the data directory, as do a saved conversation's photos, voice clips and documents, one folder a conversation, deleted with it: its items name them by `file_id` rather than carry base64. An `input_image` or `input_file` part may name any of the user's files by `file_id`, as OpenAI's may. A file's id comes from its folder and name, so renaming it changes its id.
- **`/v1/audio/speech`:** text to speech, streamed as raw 16-bit 24kHz mono PCM.
- **`/v1/audio/transcriptions`:** speech to text.
- **`/v1/audio/translations`:** speech in any language to English text. The LLM hears the audio and translates it.
- **`/v1/audio/classifications`:** the sounds in audio, such as speech, music, a doorbell or a smoke alarm; not an OpenAI endpoint. See [Sounds](../guides/classify-sounds.md).
- **`/v1/audio/diarization`**, **`/v1/audio/speakers`** and **`/v1/audio/speakers/identify`:** who spoke when in a recording, and voices enrolled by name; not OpenAI endpoints. See [Voices](../guides/tell-voices-apart.md).
- **`/v1/audio/pitch`:** the note in a recording, how many cents sharp or flat, and for an instrument, the nearest string and which way to turn it: a tuner; not an OpenAI endpoint. See [Tuning](../guides/tune-an-instrument.md).
- **`/v1/audio/denoise`:** speech with the background noise taken out; not an OpenAI endpoint. See [Noise removal](../guides/remove-noise.md).
- **`/v1/rerank`:** puts documents in order of how well each answers a query, with Qwen3-Reranker, as Cohere's and Jina's rerank APIs do; not an OpenAI endpoint. See [Documents](../guides/search-your-documents.md).
- **`/v1/embeddings`:** vectors from EmbeddingGemma 2, 768 numbers, or 128, 256 or 512 with `dimensions`. Beyond OpenAI's API, an input may also be an `image_url` or `input_audio` content part; images, audio and text share one vector space.
- **`/v1/depth`:** how far things in a photo are from the camera, in meters; not an OpenAI endpoint. See [Depth](../guides/measure-distance.md).
- **`/v1/detect`:** the objects or faces in a photo, where they are and how far away; not an OpenAI endpoint. See [Objects](../guides/find-objects-and-faces.md).
- **`/v1/segment`:** where things you name are in a photo, such as "the cup", and how far away; not an OpenAI endpoint. See [Finding things](../guides/find-things-by-name.md).
- **`/v1/lines`:** the line a robot car follows, such as tape on a floor, or a road's lanes, and how far off it the car is; not an OpenAI endpoint. See [Lines](../guides/follow-a-line.md).
- **`/v1/video/actions`:** what people are doing across a video's frames, such as jumping jacks or waving, from a video file or from photos a board sends one at a time; not an OpenAI endpoint. See [Actions](../guides/recognize-actions.md).
- **`/v1/ocr`:** the text in a photo, such as a sign, a label or a page, line by line; not an OpenAI endpoint. See [Reading text](../guides/read-text-in-photos.md).
- **`/v1/images/classifications`:** what a photo shows from a fixed list, such as a plant's species; not an OpenAI endpoint. See [Plants](../guides/identify-a-plant.md).
- **`/v1/images/edits`:** edits a photo, as OpenAI's endpoint does, with `model` naming the edit: `remove_background`, `erase`, `upscale` or `brighten`. See [Photos](../guides/edit-and-rank-photos.md).
- **`/v1/images/quality`:** scores how good photos are, and picks the best of a burst; not an OpenAI endpoint. See [Photos](../guides/edit-and-rank-photos.md).
- **`/v1/classify`:** sorts text into labels the request names, such as a voice command's intent, in milliseconds; not an OpenAI endpoint. See [Fast commands](../guides/classify-commands.md).
- **`/v1/models`:** the loaded engines; `/v1/models/{model}` returns one. Beyond OpenAI's fields, each says its `kind` (`llm`, `tts`, `stt`, `embedding`, `depth`, `detection`, `sound`, `classification`, `image_edit`, `image_quality`, `ocr`, `segmentation`, `face`, `pose`, `image_classification`, `noise_removal`, `speaker`, `line`, `action`, `pitch` or `rerank`), and where the engine knows them, the `model` it loaded, such as `gemma-4-E2B-it`, and the `backend` it runs on. The models the LLM engine can [switch to](../guides/switch-models.md) are listed too, each with its `engine`, the `modalities` it takes (`text`, `image`, `audio`), its file's `size`, the `context` length it loads with, in tokens, whether it can think (`thinking`) and call tools (`tools`), and whether it's `loaded`. Model files often get those two wrong, and Gemma 4's say no to both, so [`model_facts.py`](../../src/lite_assistant/model_facts.py) corrects them by the model's name, along with the sampling its makers recommend where the file leaves it unset. The chat page offers no thinking for a model that doesn't think. `DELETE /v1/models/{model}` deletes one of those, unless it's loaded.
- **`/hub/models`:** LiteRT-LM chat models on Hugging Face, to [add](../guides/add-models.md): `GET` searches them (`search`, `sort`: `downloads`, `likes`, `trending` or `recent`), or with a repo's address as `search`, gives that repo; `POST` downloads one, streaming its progress, speed and time left.
- **`/v1/realtime`:** OpenAI's Realtime API over a WebSocket: stream 24 kHz 16-bit mono PCM in, and get the reply back as streamed PCM with its transcript, or as text. The LLM hears the audio itself, and each sentence is spoken as soon as it's written. Supports `session.update` (instructions, voice, output modalities, max output tokens, turn detection, input transcription by Moonshine, function tools), conversation items with text, images, audio and function call outputs, `conversation.item.truncate`, and `response.create`/`response.cancel`. See [Realtime](../guides/talk-in-real-time.md).
- **`/v1/voice`:** a whole spoken turn: audio in, the spoken reply out (see below).
- **`/`:** a chat page; see [The chat page](../guides/use-the-chat-page.md). **`/voices`** lists the voices.
- **`/v1`:** an index of every `/v1` endpoint, whether a chat model is loaded, and where the docs are; OpenAI's own `/v1` is a 404. **`/llms.txt`** says what the server is and how to call it, for AI agents, as the [llms.txt](https://llmstxt.org) convention does. Neither needs a key.

The server is a FastAPI app. Engines are discovered at startup from the `lite_assistant/engines` package.
